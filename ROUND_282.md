## 2b. The owner's review of the paper: four corrections

The owner reviewed the paper before publication and named four things to fix. All four were real, and
all four are fixed in the source:

1. **§1 contradicted §7.** §1 said the work was static only, "not one byte was sent to the camera",
   while §7 reported 22 port probes and an SSH exchange with the camera. Fixed: §1 now says the work on
   *the file* is static and that it is complemented by exactly one bounded observation of the live
   device — TCP connects to three ports and a single SSH handshake, on the owner's own camera, with no
   authentication, no payload written and nothing sent to any other host.
2. **The severity of the shipped private key was overstated.** Table 3 gave it a *remote* vector
   ("impersonating a camera to a trusting client"), but §7 measures that the camera does not use this
   key. It is not a vulnerability but an unused private key in a public image — bad hygiene. Fixed: the
   row now reads "measured *not* to be the camera's live identity; hygiene; no vector demonstrated",
   and the impersonation case is named for what it would need: a client that pinned this key from
   somewhere else. `CWE-321/798` is kept as the class of the weakness itself, not of an exploit.
3. **"The host key is created on every boot" was a finding built on an unmeasured premise.** Table 3
   listed it as `CWE-1188`, while §7 admits that the reboot behaviour was never measured — and the
   abstract drew the conclusion "the device has no identity a client can verify" from it. Fixed: the
   row is marked **hypothesis**, the abstract now says what was *not* measured, and the decisive
   measurement is named (one run before and one after a power cycle). I cannot run it: it needs the
   camera switched off and on, which is the owner's to do.
4. **The abstract promised more than the camera section delivers.** Fixed: the abstract now carries the
   limitations — signature verification on the device, rollback protection, the parser's robustness,
   behaviour on an interrupted update, the debug interfaces — and states that the trust boundary sits
   outside the file.

## 2c. Fifteen names had been lost from the paper — found by the owner reading, not by an instrument

The owner also read the text extracted from the printed PDF and found holes in it. They are real, and
they were in the round-281 delivery as well: **fifteen inline fragments were missing from the source of
the paper, in twelve sentences** — `0800_appli/tmp/ssh/sshd_config`, the `HostKey` line itself,
`/usr/bin/create_host_key.sh` with the `ssh-keygen` command inside it, `0700_part_image/dev/nflasha5`,
`PasswordAuthentication no`, `BEGIN OPENSSH PRIVATE KEY`, `CMS_EncryptedData_it`, and the names of the
instruments (`paper_check.py`, `selftest_paper.py`, `layout_check.py`, `audit/checks.py`,
`verify_findings.py`, `round279_check.py`, `MAC_FINGERPRINT.sh`, `publication/run_all.sh`). The full
table, with the artifact each name comes from, is F167 in `publication/FAILURES_282.md`.

The point of this subsection is not the repair but the gap: **`paper_check.py` guards the numbers (all 98
were present, so it stayed green), and `layout_check.py` measures the boxes that are there — text that is
gone has no box, no overlap and no overflow.** An instrument that checks what is present cannot notice
what is absent. Two of the fifteen holes were found by the owner reading the print; the other thirteen
were found by searching the source for the artefacts a dropped token leaves behind.

What closes the gap is `publication/string_check.py`, in three routes: 46 names the paper's claims rest
on must be present in the source (route A) *and* in the text extracted from the printed PDF (route B);
and the source is searched for the artefacts of a dropped token (route C), with its own control line. It
is green now (46/46, route C 0, both controls firing), and `publication/selftest_string.py` proves routes
A and B can go red (`source=False pdf=True` for a source-only removal, `source=False pdf=False` once the
PDF is rebuilt). Both instruments are steps of `run_all.sh`, and a red step now stops the run: every
stage that can go red is checked for its exit code instead of being piped into `tail`.

Two further names were missing from the paper altogether and are now in it: `key_cxd90057_k8`, the key
that opens the body, and `/dev/nflasha15`, the `/usr` image member.

## 2d. Appendix A was unreadable — the third blind spot of the round

The owner also reported that pages 14–15 of the PDF were "a grid of ones". Measured, he was right
about the effect and it was not an OCR artefact this time: the appendix was a four-column table at
`\scriptsize`, where one mono character is 5.038 pt, so the number column held 22 characters per line
and the 16-hex sha256 column printed its digits as fragments starting at the same x — 294 text lines
for 98 rows, 2.88 lines per row (F169 in `publication/FAILURES_282.md`). `layout_check.py` cannot see
this: there is no overlap and no overflow, the words sit inside their own cells. That is the same shape
as F167 — an instrument that checks what is present and where, but never whether it can be read.

Fixed: the table is now grouped by artifact (the path and its sha256 prefix printed once per group, 12
groups) with two wide columns, so every cell fits in at most two lines. Printed result, measured:
pages 13–14, tallest row 3 lines, mean **1.93** lines per row, and a header that is one readable line.
Two checks now cover it: the generator estimates each cell's line count at the measured character width
and stops the build above two lines (with a control), and `publication/appendix_density.py` measures
the printed table the same way (tallest row ≤ 3, mean ≤ 2.5) with a synthetic over-full row that the
code must flag — that control found a bug in the instrument itself on its first try.

## 3. The typeface: what was wrong, what it is now

The first edition was set in **DejaVu Serif** 11 pt. It is a wide, heavy face — good for a screen UI,
tiring for fifteen pages of prose. The paper now uses:

* **TeX Gyre Pagella** for the body text (a palatino-style face: large x-height, open counters, narrow
  enough to keep the line length sane),
* **TeX Gyre Pagella Math** for the formulas (loaded through `unicode-math`, so the formulas match the
  text instead of staying in Computer Modern),
* **DejaVu Sans Mono** for the hex dumps and the hashes — this paper is full of them, and there the
  full ASCII range at a legible weight matters more than style,
* 12 pt body instead of 11 pt.

Measured on the same machine with the same instruments:

| | old (DejaVu Serif 11 pt) | new (Pagella 12 pt) |
|---|---|---|
| pages | 14 | 15 at first, **14** after the appendix was regrouped (§2d) |
| mean characters per prose line | 73.7 | 76.6 |
| ink coverage of a body page (mean grey < 128) | 4.217 % | 3.411 % |

The change had to be paid for, and the payment is a good example of why the instruments exist: with
the new metrics one long unbreakable token left the type area — `localhost:15740` on page 6, 9.6 pt
past the margin — and `layout_check.py` caught it (`overflows past the margin 1`). Explicit break
points were added after the colon (`localhost:\allowbreak15740`), which add no printed character; the
document is clean again (0 overlaps, 0 overflows, 0 ink outside the safe frame). All 98 numbers stayed
bound to their artifacts on the rebuilt PDF (`paper_check.py` 5/5 green, its control red).

What the font change does **not** touch: no number, no claim, no figure. The paper's content is
byte-identical in meaning; only its presentation changed.

## 4. How this round is checked

* `sh publication/run_all.sh` — the whole chain afresh: the audit instruments, the numbers, the PDF,
  the binding of every number to its artifact, two layout routes, both self-tests, the manifest.
* The audit instruments themselves, re-run after translation: `checks.py` 15/15 (+3/3 controls),
  `report_check.py` 2/2 (+3/3), `round277_check.py` 13/13 (+5/5), `round278_check.py` 17/17 (+5/5),
  `round279_check.py` 28/29 with **1 SKIP** (the camera does not answer from this container — a skip is
  not a pass), `verify_findings.py` 47/47 (+5/5).
* `python3 publication/scan_cyrillic.py` — a scan for U+0400–U+04FF over every text file of the
  package with a planted-line control: 0 hits, control found. (Binaries — the firmware, the unpacked
  stream, the PDF — are out of its scope and it says so; the printed paper is covered by
  `paper_check.py`, which requires every one of its 98 numbers to be in the printed text.)
* The delivery: every shipped file is read back **from the volume** and compared by sha256
  (`audit/make_282_delivery.py`), and `sha256sum -c MANIFEST.sha256` runs in the delivered folder.

## 5. What this round does not claim

* That no Russian remains anywhere in the owner's machine — only that none remains in this package.
* That the typeface is now "beautiful": it is *lighter and roomier*, and that is measured (ink
  coverage 4.217 % -> 3.411 %, mean line 73.7 -> 76.6 characters). Whether it reads better is the
  owner's judgement, not a measurement I can make.
* That the live camera measurements hold today: they were made on 2026-10-04 at 17:06–17:43 and are
  kept as witness files; today the camera is unreachable.
